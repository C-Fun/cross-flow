## 2. 改动清单与因果解释

### 2.1 v1 → v2：自适应归一化（修复第一次坍缩）
**现象**：v1 在 50k 步后采样图完全不变，FID 卡在 ~150；网络对 r 不敏感——F(z_t, r=t) ≈ F(z_t, r≈0)，即退化成"纯去噪器"。

**诊断**（在 230k EMA 权重上实测，`scripts/diag_collapse.py`）：
- JVP 在 fp32/bf16 下均与有限差分一致 → 不是实现错误。
- 各时间区域的裁剪前梯度范数：对角线 t=r=1e-3 为 **5623**，t=r=0.01 为 46，其余区域 0.2–0.7，生成区（t≈1, r→0）≈ 0。
- 根因：eq.(11') 的权重 r/t² 在 L2 残差下以平方放大（≈1/t² 最高 1e8），再配合 grad-clip=1.0，每步更新几乎全是"解码近干净 latent"的方向，生成端没有梯度。

**改动**：逐样本 `‖R‖²/sg(‖R‖²+c)` 归一化（MeanFlow/iMF 的做法），各区域梯度拉到同量级；time_eps 1e-4 → 1e-2。

**效果**：FID 147 → 79（同样 18 万步），模型开始使用 r，生成端有语义。**但这一步是"对症不对路"**：它抹掉了论文有意保留的 1/t 权重（解码器端的强调），后来在 v4 被 L1 方案替换。

### 2.2 v2 → v3：仅算力
同配方在 8×H200 上跑满 400k 步：FID 65，平台化（最后 60k 步只降 0.6）。说明该配方的天花板在 65 左右，不是欠训练。

### 2.3 v3 → v4：对齐论文配方（通读论文后）
重读论文全文（19 页，含附录 B/C）后发现之前的阅读笔记遗漏了 4 处实质差异，v4 一次补齐 3 处：

| 项目 | 论文 | v3 | v4 |
|---|---|---|---|
| 编码器 | **VA-VAE f16×32ch**（论文测的最差选项"SD-VAE 16ch"也只 +1.5） | SD-VAE **f8×4ch**（信息量 1/4，论文从未测过） | VA-VAE，官方 latent 统计量归一化 |
| 感知损失 | DINOv3-B 特征 Huber，施加在**修正预测** x̂ = F + t(t−r)/r·sg(dF/dt) 上，**覆盖全部 (t,r)**，不乘 r/t² | VGG-LPIPS，**只在 r=t 对角线**（50% 样本） | 与论文一致（timm DINOv3-B，原生 256 输入） |
| 像素损失 | **L1** | L2 + 自适应归一化 | L1，去掉归一化 |
| 预算 | batch 2048 × 160 epoch | batch 256 × 400k（样本量一半） | 与论文一致（4×64×8 累积） |

**为什么重要**：论文消融里"去掉感知损失"代价 +27.7，"去掉 GAN" +6.3；v3 的感知损失只覆盖对角线样本，而我之前的诊断已证明生成端从核心损失几乎拿不到梯度——等于生成端**完全没有像素级监督**，所以 v3 的 65 实际上对应论文"两者都无"的 50.65 那一格再叠加差编码器。L1 则让 r/t² 权重只线性放大（≤1/t），不需要归一化就能稳定，同时保留论文对解码端的强调。

**结果**：v4 跑到 66k 步 FID 99 平台——**反而比 v3 差**。

### 2.4 v4 → v5：Muon + 端点裁剪（修复第二次停滞）
**诊断**（65k EMA 权重）：
- 解码端健康（t=0.01 重建 PSNR 28.5 dB，比 VA-VAE 自带解码器还高）。
- **硬伤**：高噪声端 |dF/dt| 均方根 6–8，乘上系数 t(t−r)/r（r 下界 0.01 时可达 97）后，修正预测 x̂ 在非对角线样本上数值爆到 10³–10⁴。真实采样分布下 27% 的非对角样本是这种垃圾，占感知损失的 36%，而 DINO 对它们饱和、梯度≈0 → **感知损失恰恰在决定一步生成质量的高 t 区域没有信号**，模型学不到轨迹一致性，dF/dt 居高不下，死循环。
- 梯度失衡仍在：L1 下对角线 t=0.01 梯度 11.8 vs 其余 0.02–0.5（≈50×，v1 是 10⁴×），grad-clip 1.0 使解码样本仍主导更新。

**改动**（都是论文明说而我没做的）：
1. **Muon 优化器**（`torch.optim.Muon` 作用于 84 个 Transformer 权重矩阵，AdamW 管 tokens/norm/bias）：更新经正交化、幅度与梯度尺度解耦，天然消除"少数样本主导"。
2. **time_eps 0.05**（论文"mild endpoint clipping"，数值未给）：1/t ≤ 20，x̂ 系数 ≤ 17。
3. **去掉 grad-clip**（我加的，论文没有）。
4. x̂ 送入 DINO 前 clamp 到 [-1,1]（数值保护）。

**结果**：20k 步 FID 66.8（v4 同点 297），100k 步 23–24，IS 77。这是最大的一次提升，证明前两次失败的共同本质是**优化动力学被 r/t² 权重劫持**，而论文的 Muon + 裁剪正是针对它的。

### 2.5 工程层面（不影响算法，但决定了能否跑）
- `torch.func.jvp` 与 DDP 不兼容 → 手动广播参数 + all-reduce 梯度；RoPE 改为实数 cos/sin 实现以兼容前向 AD。
- bf16 JVP 与 fp32 校验（相对误差 1.4%，余弦 0.9999）；fp32 在 64 GB 卡上 OOM。
- ROCm：`cudnn.benchmark` 触发 MIOpen 穷举搜索卡一小时；DeltaAI：注入的 aws-ofi-nccl 插件在 batch step 里 double-free，需 `NCCL_NET=Socket`。
- 多次 GPU 共享/硬件故障导致的崩溃循环，由 Slurm afterany 链 / 本地重启循环自动续训。

## 3. 与论文剩余的差距（23 vs 8.86）及可能原因

按影响大小排序：

1. **对抗损失缺失（论文 +6.3，但对"高频细节/纹理"的作用可能远大于 FID 数字所示）**。v5 的采样图类别正确、构图合理，但仍有噪点和纹理伪影——这正是 L1+感知损失而无判别器时的典型相貌。论文的 dinoGAN（冻结 DINO + 判别头，hinge，w(t)=(1−t)² 时间加权）可以复用我们已有的 DINO 特征，预计 +10–15% 步时。
2. **x̂ 的无界系数仍是结构性弱点**。time_eps 0.05 把系数压到 ≤17 而不是 97，但没有消除；论文"mild clipping"的真实数值未知，若他们用更大的 r 下界或对感知项单独裁剪，高 t 区域的感知信号会更干净。可做的消融：对感知项的 x̂ 系数单独加上界（如 ≤5），或只在 r ≥ 0.1 的样本上计算感知损失。
3. **FID 在 70k 后微升（23.3 → 24.3）**：lr 8e-4 恒定无衰减；论文未写是否衰减。EMA 0.9999 在 100k 步、batch 2048 下偏慢；可试 0.9995（论文从 {0.999, 0.9995, 0.9999} 中选）。
4. **DINOv3 感知损失的细节**：论文用 "DINOv3-B features + Huber"，层/归一化/是否含 CLS 未说明；我用全部 token（含 5 个 prefix token）的 Huber，delta=1.0。差异可能影响几个点。
5. **类别条件的 16 个 context token vs 我们的 12 个**、shift α=√2 的时间分布——影响应很小。
6. 评估协议：我们的 10k 样本 FID 偏高 2–3 点；正式对比需跑 50k。

## 4. 建议的下一步（如果继续追论文数字）
1. 先用 50k 样本评 v5 的 best checkpoint（80k），拿到可比数字。
2. 加 dinoGAN（复用感知特征），(1−t)² 权重，判别器延迟 5k 步启动，从 v5 80k 续训 50k 步看增量。
3. 同时跑两个廉价消融：感知项 x̂ 系数上界 5；EMA 0.9995 + 最后 20% 步 lr 余弦衰减。
